MASTER DEVELOPMENT PROMPT — LabRepo

You are a senior full-stack AI software engineer. Your task is to build
a production-quality application called LabRepo.

Mission

LabRepo solves a simple problem: students frequently lose their college
laboratory work because it is scattered across laptops, USB drives, or
gets erased after OS reinstalls. Build a fast, minimal, reliable
repository that lets students safely organize and retrieve their lab
work.

Core principle: Reliability > Features UX > UI Functionality > Visual
polish

Existing Stack

-   Astro (already configured)
-   Clerk Authentication (already integrated)

Do NOT replace Astro or Clerk.

Backend

Build whatever backend is required using TypeScript (Fastify or Express
preferred).

Database

Use SQLite.

SQLite stores ONLY metadata: - Academic sessions - Subjects - Works -
File metadata - Recycle bin information - Auto-delete settings

Uploaded files must NEVER be stored in SQLite.

Storage

Implement a Storage Adapter abstraction.

Initially emulate AWS S3 using fake credentials and a mocked provider.

Use placeholder environment variables such as:

AWS_ACCESS_KEY=fake_access_key AWS_SECRET_KEY=fake_secret
AWS_BUCKET=fake_bucket AWS_REGION=fake_region AWS_ENDPOINT=fake_endpoint

At the end of development provide a “Production Setup” guide
explaining: - Creating an AWS S3 bucket - IAM user creation - Required
permissions - Environment variables - Switching from mocked storage to
real S3 without changing application code

Users

Authentication is handled entirely by Clerk.

Each user can only access their own data.

Data Hierarchy

User └── Academic Session └── Subject └── Work └── Files

Storage path example:

user-id/ 2026-2027/ Machine Learning/ Experiment 5/ train.py
notebook.ipynb

Features

Academic Sessions

-   Create
-   Rename
-   Delete
-   Optional auto-delete after academic year completion

Subjects

-   Create
-   Rename
-   Delete

Subject names map directly to folder names.

Upload Wizard

Flow: 1. Select subject 2. Enter work title Default = current date 3.
Select multiple files 4. Upload

Rules: - Multiple file upload supported - Total upload size per upload
session = 25 MB maximum - Validate before upload starts

Allowed Extensions

Programming / AI / Data Science only, including:

py, ipynb, js, jsx, ts, tsx, c, cpp, java, kt, cs, go, rs, swift, php,
rb, r, scala, sql, html, css, scss, json, yaml, yml, xml, md, txt, csv,
parquet, feather, pkl, joblib, onnx, pt, pth, keras, h5

Reject unsupported extensions.

Preview

Preview text-based source files in-browser without downloading.

Include syntax highlighting where appropriate.

Binary files should only be downloadable.

Download

Support: - Single file - Entire work - Entire subject - Entire academic
session - Entire account

Bulk downloads should be ZIP archives.

Delete

Soft delete only.

Move deleted content to Recycle Bin.

Retention = 7 days.

Recycle Bin supports: - Restore - Delete forever

Display remaining days.

Search

Instant search across: - Subject - Work title - Filename

Sorting

Support: - Newest - Oldest - A-Z - Z-A - Recently updated

Filtering

Support filtering by: - Academic session - Subject - File extension -
Upload date

UI

Dark mode only.

Responsive.

Desktop and mobile friendly.

Liquid glass inspired design.

Keep interface minimal.

Avoid feature bloat.

Security

Validate: - Clerk authentication - Ownership - File extension - Upload
size - Sanitized filenames

Performance

Use asynchronous uploads.

Lazy-load previews.

Optimize for responsiveness.

Deliverables

Build both frontend and backend as required.

Use SQLite for metadata.

Use mocked S3 during development.

At project completion include: 1. Production Setup guide 2. Environment
variable documentation 3. Steps to connect a real AWS S3 bucket 4. Any
migration notes

When making implementation decisions always prioritize:

1.  Reliability
2.  Correctness
3.  Simplicity
4.  Maintainability
5.  Performance

Never add unnecessary features outside this specification.

ADDITIONAL REQUIREMENT — FIRST-TIME ONBOARDING EXPERIENCE

Design a dedicated first-time onboarding flow that appears immediately
after a new user signs in for the first time.

Goal: Help users understand the application and finish the minimum setup
within 60 seconds using a highly visual, step-by-step experience.

Requirements:

-   Do not overwhelm the user.
-   Prioritize clarity over aesthetics.
-   Use illustrations, icons, progress indicators, and empty-state
    visuals.
-   Keep text concise.
-   Make every step skippable except the final confirmation.

Suggested flow:

1.  Welcome
    -   Explain what LabRepo is.
    -   Illustrate how files are organized: Academic Session → Subject →
        Work → Files.
2.  Create First Academic Session
    -   Prompt the user to create their current academic session.
    -   Example: 2026–2027.
3.  Add Subjects
    -   Encourage adding commonly used subjects.
    -   Allow multiple subjects to be added quickly.
4.  Explain Uploads
    -   Show a visual mock upload wizard.
    -   Explain the 25 MB upload limit and supported programming-related
        file types.
5.  Data Safety
    -   Explain recycle bin, 7-day recovery, downloads, and optional
        academic-year auto-delete.
6.  Finish
    -   Take the user directly to an empty dashboard with a prominent
        “Upload your first lab work” call-to-action.

UX Requirements: - Dark mode. - Mobile-first but desktop-friendly. -
Liquid glass inspired visuals. - Clear illustrations and informative
empty states. - Smooth transitions. - Accessible keyboard navigation. -
Progress indicator (e.g., Step 2 of 6).

The onboarding should make a first-time user immediately understand the
product without requiring documentation.
